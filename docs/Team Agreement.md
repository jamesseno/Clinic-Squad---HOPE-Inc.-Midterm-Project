# Sprint 1: Team Governance & Guidelines

## 1. Team Working Agreement
* **Communication:** We will use our designated team chat (e.g., Messenger or Discord) for daily updates and quick questions. Urgent issues should be raised via direct call.
* **Meetings:** Team members are expected to attend sprint planning sessions and standups on time. If unable to attend, notify the team at least 2 hours in prior.
* **Coding Standards:** Write clean, readable code with descriptive variable names, consistent formatting, and meaningful commit messages (following conventional commits like `feat:`, `fix:`, `docs:`).
* **Conflict Resolution:** Disagreements regarding implementation will be discussed openly during team syncs. If consensus cannot be reached, the Scrum Master will help guide a final decision based on project requirements.

---

## 2. Definition of Done (DoD)
A task or user story is only considered **Done** when:
* [ ] Code is written, tested locally, and meets the acceptance criteria.
* [ ] Documentation has been updated (if applicable).
* [ ] Code has been pushed to a feature branch.
* [ ] A Pull Request (PR) has been created, linked to the respective issue, and reviewed/approved by at least one teammate.
* [ ] The PR is successfully merged into the `main` branch without breaking builds.

---


## 3. Role Guide
* **Scrum Master (SM):** Facilitates sprint ceremonies, removes blockers, tracks team progress on GitHub issues, and ensures Scrum practices are followed.
* **Developers:** Implement features, write clean code, perform peer reviews, and resolve assigned bugs or issues.
* **Quality Assurance (QA) / Testers:** Verify that implemented features meet acceptance criteria, perform manual or automated testing, and log any bugs found during the sprint.
